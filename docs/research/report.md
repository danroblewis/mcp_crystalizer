# Replacing an LLM agent with programmatic MCP traversal: research synthesis

## 1. Bottom line

Yes. Seven independent lines of work converge on the same lifecycle, and at least two of them report production use on on-call/incident workloads: record the agent's tool-call traces, have an LLM (or, for extraction, a classical program synthesiser) emit *executable artefacts* (extractors, query templates, link rules) rather than answers, gate those artefacts with mechanical audits against held-out traces, then run them with zero model calls and demote back to the agent only when they stop validating. Microsoft's **Progressive Crystallization** paper reports that this took the deterministic share of an AIOps incident system from 0% to 45% in eight months with >70% lower per-incident agent cost ([2607.07052](https://arxiv.org/abs/2607.07052); note this is a 4-page paper and the mechanism descriptions are one sentence each); the **Tool-Making** paper did the same for alarm triage over MCP backends ([2607.08010](https://arxiv.org/html/2607.08010)). The "graph database with an odd query language" framing already exists as shipped, LLM-free engines: Red Hat's **korrel8r** models each backend as a domain whose classes are joined by template rules that render native queries and silently skip when a field is missing ([korrel8r](https://github.com/korrel8r/korrel8r)); Grafana **Correlations** productise the single hop with regex-named-group extraction into a target query template ([Grafana](https://grafana.com/docs/grafana/latest/administration/correlations/correlation-configuration/)); Apollo **Connectors** express "each backend call is a reference resolver keyed by `@key` fields" declaratively, with a query planner that decides fetch order and batching ([Apollo Connectors](https://www.apollographql.com/docs/graphos/schema-design/connectors/entities)).

The fuzziness decomposes into mechanisms that are each in-process. For "which substring": a typed regex mask catalog plus gazetteer (Drain3, DeepParse, Aho-Corasick), and, the main revision from the gap-fill research, **FlashExtract-style position programs** `RegPos((r1,r2),k)` synthesised from the recorded `(text, chosen span)` pairs with no model at all ([FlashExtract](https://www.microsoft.com/en-us/research/wp-content/uploads/2016/12/pldi14-flashextract.pdf)). For "which candidate result": a local hybrid index (SQLite FTS5 trigram + BM25 + sqlite-vec with static embeddings, fused by RRF). For "how to phrase the search": push the fuzziness into the backend query language via a fixed precision ladder (exact phrase → AND of tokens → OR of tokens → prefix → edit-distance fuzzy where the backend supports it), and use backend highlighting (Elasticsearch/Logz.io `highlight`, Confluence `excerpt`, `git grep --column`) to localise the matched span for the next hop. For codebase hops: a def/ref graph with personalized PageRank.

The honest caveats: **Compiled AI**'s DocILE table shows LLM-free regex matching the runtime LLM on ID-shaped fields but collapsing to roughly 10–20% on semantic fields (names, amounts) ([2604.05150](https://arxiv.org/abs/2604.05150)); **Regel**'s PBE-only mode solved just 26% of 322 realistic regex tasks from ~4 positive and ~5 negative examples, which is the honest ceiling for "examples alone" when no lexical cue exists ([Regel](https://arxiv.org/abs/1908.03316)). So plan for a small, schema-fixed LLM call for phrasing a search from pure ticket prose and for the final narrative, and reserve zero-LLM execution for the ID-plumbing steps that make up most of the chain. Nothing in the catalogue below requires a search or vector server; the stores are JSON, SQLite, and static per-repo artefacts.

## 2. Pattern catalogue

### P1. Trace-grounded crystallization with evidence-gated promotion and circuit-breaker demotion
Record every agent run as an ordered list of tool calls with raw inputs/outputs; parse traces into a DAG, parameterise instance-specific values (ticket key, service, SHA, pod, time window), detect the branch conditions the agent acted on, and mark human gates. Promote a template to LLM-free execution only after a track record. As we read Progressive Crystallization, its thresholds are ≥10 identical-sequence runs to reach "hybrid" and ≥50 runs with ≥99% classification consistency plus a regression suite auto-generated from successful traces to reach "deterministic", with a circuit breaker that demotes on failure or acceptance-test regression (their example: a firmware update changed an output format, the parser failed, the playbook fell back to the LLM tier). Because the paper is thin, confirm these thresholds against the text before building on them. **TraceCompiler** adds the missing formalism: classify every argument binding as constant / user input / copied from prior output / deterministic transform / LLM decision, keep edges only with evidence tuples, and emit LLM nodes only for bindings evidence cannot resolve ([2608.02680](https://arxiv.org/html/2608.02680)). Stagehand ships the same loop for browser agents (cached action replays first, LLM self-heals on failure) ([Stagehand](https://docs.stagehand.dev/v2/best-practices/caching)).
*Sources:* [2607.07052](https://arxiv.org/abs/2607.07052) (production, thin on mechanism), [2607.08010](https://arxiv.org/html/2607.08010) (production), [2608.02680](https://arxiv.org/html/2608.02680) (research), [AWM 2409.07429](https://arxiv.org/html/2409.07429v1) (rule-based slot inducer), [AgentRR 2505.17716](https://arxiv.org/html/2505.17716v1) (low-level vs high-level replay taxonomy). *Evidence:* strong on outcome, weak on code recipe.
*Applies here:* PagerDuty alert type + service + error signature is the trigger key; the recorded jira→slack→grep→confluence→chronosphere+logz chains become templates; replayed traces are the regression suite. *Limits:* the paper never says how parameters are pulled from unstructured output; that is P3/P5/P12.

### P2. LLM writes the extractor, audits gate the cache (call the LLM last)
The one-time LLM call emits a spec (CSS selector map, regex with named groups, JSONPath, 20–50-line function) rather than a value, and it is cached only after three audits: structural (matches exactly one span), value (format check: `[A-Z]+-\d+`, sha1, ISO timestamp, k8s pod name, service from catalog), and cross-example (also yields the value the agent actually used on 2+ held-out traces; a spec that only works on the sample "likely encodes a value specific to the sample page"). Cache a *list* of candidate extractors per (template, step) and take the first that validates; try non-LLM healing (difflib similarity to the previously extracted value) before regenerating. Compiled AI gives the cost model: break-even at roughly 17 executions and large token savings at 1,000 executions (as we read the paper; exact ratios not re-verified). Tool-Making's Appendix D shows how to get labels when you only have traces: generate N candidates, pseudo-label by majority vote, repair loop with a reflector (N=1 loses 8.6pp). With P12 available, this pattern becomes the *second* resort: run a deterministic synthesiser on the trace spans first and call the LLM only when its version space empties.
*Sources:* [ScrapingBee](https://www.scrapingbee.com/blog/ecommerce-scraping-cascade-scrapy-local-llm/) (production blog), [2604.05150](https://arxiv.org/abs/2604.05150) (prototype, two benchmarks), [2607.08010](https://arxiv.org/html/2607.08010), [Is PBE solved by LLMs 2406.08316](https://arxiv.org/abs/2406.08316) (caution: few-example generalisation is poor, hence held-out audits).
*Applies here:* every recorded step of the form "took X from result R, put it in param P of the next call" becomes a span-labelled example; Jira/PagerDuty JSON fields are Tier 1 (read structured first), Slack/log/wiki regexes are Tier 4. *Limits:* value audits must be authored per parameter type; semantic fields stay LLM-bound.

### P3. Typed mask catalog + gazetteer (mask-first entity extraction)
Split extraction into (a) shape-based: a catalog of typed regexes (TRACE_ID, POD, JIRA_KEY, SHA, HTTP_STATUS…) consumed by Drain3 `masking_instructions`, after which `match()` + `extract_parameters()` return ordered `(value, mask_name)` slots with no tree mutation; and (b) catalog-based: an Aho-Corasick/FlashText automaton built from one-time MCP dumps (Jira project keys and components, Slack channel names, k8s namespaces, service names from Chronosphere label values, PagerDuty services, Confluence spaces) that scans every result for typed mentions with offsets, LeftmostLongest resolving `payments` vs `payments-api`; RapidFuzz `token_set_ratio`/`partial_ratio_alignment` as a thresholded fallback for aliases and to recover the exact span. **DeepParse** benchmarks exactly this split: LLM synthesises the regex catalog offline (entropy-greedy sampling of ~50 diverse lines, output forced to a Python list, `re.compile` validation, re-prompt on failure), Drain3 runs it forever; 97.6% parsing accuracy vs 33.5% for vanilla Drain, ~100× faster than per-line LLM parsing. **Regexulator** is the recipe for prose: examples are `(text, [(start,end)])` spans, a tree search shows the LLM its own false positives/negatives on a validation split, and exact-match F1 reaches ~0.90 from 8–15 snippets (0.62 from 4–7). **grex** learns the value-shape regex from the set of chosen values alone (positive-only, DFA-minimised, Apache-2, pip + WASM) and is a zero-effort candidate generator for the catalog ([grex](https://github.com/pemistahl/grex)). The mask/entity *type* is what lets a deterministic planner route TRACE_ID→logz and SERVICE→chronosphere.
*Sources:* [Drain3](https://github.com/logpai/Drain3) (production), [DeepParse 2604.20553](https://arxiv.org/html/2604.20553v1) (research, LogHub-2k only), [Regexulator paper](https://nlp.fi.muni.cz/raslan/2024/paper6.pdf) / [repo](https://github.com/ZepZep/regexulator) (research, tiny repo), [grex](https://github.com/pemistahl/grex), [ahocorasick_rs](https://github.com/G-Research/ahocorasick_rs), [FlashText](https://github.com/vi3k6i5/flashtext), [RapidFuzz](https://github.com/rapidfuzz/RapidFuzz), [iocextract](https://github.com/InQuest/iocextract) (per-type extractor modules + refang canonicaliser), [Cortex Extractor](https://github.com/TheHive-Project/Cortex) (recursive JSON walk, typed artifacts unlock typed analyzers), [grok](https://docs.datadoghq.com/logs/log_configuration/processors/grok_parser/) / [lnav formats](https://docs.lnav.org/en/latest/formats.html) / [Mattermost autolink](https://github.com/DHaussermann/mattermost-plugin-autolink) (registry file shapes).
*Applies here:* logz.io lines, Chronosphere alert bodies, PagerDuty notes, gcloud/azure CLI output → Drain3; Slack, Jira, Confluence prose → gazetteer + synthesised regexes. *Limits:* Drain fails on human prose; gazetteers miss typos unless aliases are enumerated and produce false positives on short names (`api`, `core`); neither ranks among multiple candidates in one line, which is P12's job.

### P4. Correlation link table over a rule graph (skip-on-missing, fan-out on repeat)
A checked-in table of rows `(source class, source field/pointer, extractor, target tool, parameter template, applicability condition)` turns tool results into a navigable graph. korrel8r's rule is start class → Go template → goal-domain query string in that backend's *native* language (`k8s:Pod.v1:{namespace: "{{index .Labels "namespace" | required}}"}`); "if a template returns a blank string or raises an error, korrel8r skips the rule for that object", `range` fans out one query per repeated field, and goal search (shortest path from Jira issue to logs) / neighbourhood search (everything within N hops) replace "which tool next". Grafana Correlations add `type: regex` transformations whose named groups become variables (`service=(\w+)\.\w+` → `${application}`) and the rule that a link renders only when every variable resolves. Keep supplies ordered, CEL-guarded, first-match-wins extraction rules plus `{{ steps.x.results.0.field }}` / `foreach` templating. RESTler shows the bootstrap: infer candidate links by matching output field names to input parameter names, then a tiny annotation file (`producer_endpoint`, `producer_resource_name` as a JSON pointer, `consumer_param`) for the rest, compiled to writer/reader variables. OpenAPI Links and Arazzo are the standard vocabulary; Arazzo explicitly has no loop/forEach construct and its `regex` is only a boolean success criterion, not a capture ([Arazzo](https://spec.openapis.org/arazzo/latest.html)), so the MCP link schema must add an `extract` transform and a `forEach` binding, or borrow them from an existing DSL (P13).
The gap-fill research adds the *graph-engine* shapes for the same table: Apollo Connectors' `@key` + `@connect(http:{POST:"/jira/get_issue", body:"key: $this.key"}, selection:"…", entity: true, batch)` is one declarative entry per (entity type, key fields, tool, argument mapping, output selection), and the federation planner emits `Sequence/Parallel/Flatten(path:"hotels.@")` fetch plans with `_entities(representations:)` batching, i.e. "which tool next / fan-out / merge" done without a model ([Apollo Connectors](https://www.apollographql.com/docs/graphos/schema-design/connectors/entities), [query plans](https://www.apollographql.com/docs/graphos/reference/federation/query-plans)); Steampipe `KeyColumns` with `Require: plugin.Required` and osquery `required=True` columns are the SQL-flavoured equivalent, with free-text search modelled as a required `query` column (e.g. `slack_search`) ([Steampipe](https://steampipe.io/docs/develop/writing-plugins), [slack_search](https://hub.steampipe.io/plugins/turbot/slack/tables/slack_search), [osquery](https://osquery.readthedocs.io/en/stable/development/creating-tables/)); GraphQL Mesh's `additionalTypeDefs` + `additionalResolvers` with DataLoader batching is the Node-embeddable version ([Mesh](https://the-guild.dev/graphql/mesh/docs/guides/extending-unified-schema)). None of the graph engines do regex capture from free text; that stays in the extractor layer.
*Sources:* [korrel8r](https://github.com/korrel8r/korrel8r) (production, k8s-centric), [Grafana correlations](https://grafana.com/docs/grafana/latest/administration/correlations/use-variables-and-transformations/), [Loki derived fields / trace-to-logs](https://grafana.com/docs/grafana/latest/datasources/tempo/configure-tempo-data-source/configure-trace-to-logs/), [Keep extraction](https://docs.keephq.dev/overview/enrichment/extraction), [RESTler annotations](https://github.com/microsoft/restler-fuzzer/blob/main/docs/user-guide/Annotations.md), [OpenAPI Links](https://spec.openapis.org/oas/v3.1.0#link-object), [Arazzo](https://spec.openapis.org/arazzo/latest.html), [AutoRestTest 2411.07098](https://arxiv.org/html/2411.07098) (embedding-similarity edge inference between operations), [Firefly 2605.17558](https://arxiv.org/html/2605.17558) (one-time LLM-judged confidence-labelled tool graph over real MCP tools), [Apollo entities intro](https://www.apollographql.com/docs/graphos/schema-design/federated-schemas/entities/intro), [Hasura remote joins](https://hasura.io/docs/2.0/remote-schemas/remote-relationships/index/) (batching to avoid n+1), [SPARQL 1.1 SERVICE](https://www.w3.org/TR/sparql11-federated-query/) / [FedX bound joins](https://rdf4j.org/documentation/programming/federation/) / [Comunica in-browser](https://comunica.dev/docs/query/getting_started/query_browser_app/) (purest "bindings flow between endpoints" model, high adoption cost).
*Applies here:* `IssueToSlack` renders a Slack search from key + component; `SlackMessageToLogz` extracts a trace id and renders ES DSL; `IssueToCodeGrep` greps the error string; `CommitToConfluence` searches the runbook space for the component; `PagerDutyIncident.context` is a server-side neighbour op to reuse directly. *Limits:* no ranking beyond hit counts; time-window propagation must be added (see P14 for per-backend window encodings); korrel8r domains would be rewritten in your language.

### P5. Frozen code-mode over session-pinned MCP
Expose each MCP tool as a typed function (`./servers/<server>/<tool>.ts` from `tools/list` inputSchema), let the agent write the chain once as code that filters/joins in-process (Anthropic: 150K→2K tokens; Cloudflare: 1.17M→~1K), persist it as a skill, then execute it with no model against long-lived authenticated sessions. `mcpc` gives named sessions, `--json` output that is always spec-shaped, and the canonical no-LLM chain (`… | jq '.content[0].text | fromjson | .items[0].id' | xargs …`); `tools-get --schema` snapshots detect vendor schema drift; `--proxy` re-exposes an authenticated session locally so a browser never holds tokens. The Inspector CLI documents distinct exit-code classes for auth failures, unreachable servers and tool errors; copy that classification so a frozen chain stops cleanly (the exact code numbers were not re-verified). `toolscript` is the local, no-extra-service Deno sandbox variant.
*Sources:* [Anthropic code execution with MCP](https://www.anthropic.com/engineering/code-execution-with-mcp) (opinion, no code), [Cloudflare Code Mode](https://blog.cloudflare.com/code-mode/), [mcpc](https://github.com/apify/mcpc), [Inspector CLI](https://modelcontextprotocol.io/docs/2026-07-28/tools/inspector/cli), [toolscript](https://github.com/mkerix/toolscript), [mcpo](https://github.com/open-webui/mcpo), [MCP tools spec](https://modelcontextprotocol.io/specification/2025-06-18/server/tools).
*Applies here:* one session per server (jira/slack/confluence/chronosphere/logz/pagerduty/gdrive/gcloud/azure/arc); `readOnlyHint` gates which tools the planner may fan out speculatively. *Limits:* in the servers whose source or docs we read, results arrive as text content that must be parsed (korotovsky's Slack server returns CSV rows; Chronosphere, PagerDuty and gcloud servers return JSON-as-text), and we found no server emitting `structuredContent` or cross-server `resource_link` blocks; treat "no vendor server does" as an absence-of-evidence hypothesis rather than a survey result. Rovo's deferred `discover`/`executeRead` tools need `discover` captured in traces ([Rovo tools](https://support.atlassian.com/atlassian-ai-gateway/docs/supported-tools/)).

### P6. Local hybrid tool-result index (FTS5 ×2 + sqlite-vec + RRF + rerank rules)
Normalise every result into one `items(id, source, ts, ref, title, body)` row and hang three indexes on it in the same file: an FTS5 index with `unicode61 tokenchars '-_./:@'` so `JIRA-1234` and pod names stay whole tokens for BM25 with column weights; a trigram FTS5 index so a partial pod name, commit prefix, or ticket key is an indexed substring lookup (≥3 chars) with `highlight()`/`snippet()` localising the span extractors should regex; and a `vec0` table of Model2Vec static embeddings partitioned by source. Fuse with the pure-SQL RRF statement (`1/(k+rank)` per leg, tunable weights) and fit weights from traces so the item the agent actually used next ranks first. Semble's README reports that hand-written rerank rules on top of BM25 contributed more than adding the vector leg; the exact NDCG deltas we quoted earlier were not re-verified, but the direction is decision-relevant: put the one-time LLM budget into rerank rules (boost `#incidents-*`, boost log lines whose service equals the ticket component, penalise stale Confluence pages) rather than embeddings. An HN report runs the identical stack over agent tool outputs with hash-based incremental reindexing.
*Sources:* [FTS5](https://www.sqlite.org/fts5.html), [sqlite-vec](https://alexgarcia.xyz/blog/2024/sqlite-vec-stable-release/index.html), [hybrid search recipes](https://alexgarcia.xyz/blog/2024/sqlite-vec-hybrid-search/index.html), [HN 47203790](https://news.ycombinator.com/item?id=47203790), [Model2Vec blog](https://huggingface.co/blog/Pringled/model2vec) / [library](https://github.com/MinishLab/model2vec), [Semble](https://github.com/MinishLab/semble), [lucivy](https://github.com/L-Defraiteur/lucivy) (substring-across-token BM25 if trigram is insufficient), [MiniSearch/FlexSearch/Orama](https://github.com/nextapps-de/flexsearch) for browser-only.
*Applies here:* replaces "which of these 40 Slack/Confluence hits is the one"; trigram handles partial IDs in logz lines. *Limits:* FTS5 trigram queries need ≥3 characters; sqlite-vec KNN is brute-force (per its release notes); Model2Vec model sizes/dimensions and the existence of a browser package should be checked on the model cards (unverified here).

### P7. Entity catalog as foreign-key hub
Most cross-tool hops are key lookups if a small local table maps `service → jira project, slack channel, pagerduty service id, chronosphere labels, logz index, repo path, owning team`. Backstage's well-known annotations (`pagerduty.com/service-id`, `jira/project-key`, `github.com/project-slug`) and relations (`ownedBy/ownerOf`, `dependsOn`) are the vocabulary; CODEOWNERS last-match glob rules and Sentry ownership rules (`path:src/api/* #backend-team`) resolve file→team; Sentry suspect commits is a fully deterministic stack-trace→code-mapping→git-blame→commit chain. The backends' own discovery calls populate the table cheaply: Grafana MCP `list_prometheus_metric_names(regex)` / `list_loki_label_values(matchers)`, Chronosphere `list_prometheus_label_values(label_name, selectors)` and `list_log_field_values`, PagerDuty `list_services` ([mcp-grafana](https://github.com/grafana/mcp-grafana), [Chronosphere prometheus tools](https://raw.githubusercontent.com/chronosphereio/chronosphere-mcp/main/mcp-server/pkg/tools/prometheus/tools.go)).
*Sources:* [Backstage annotations](https://backstage.io/docs/features/software-catalog/well-known-annotations/), [Backstage relations](https://backstage.io/docs/features/software-catalog/well-known-relations/), [hmarr/codeowners](https://github.com/hmarr/codeowners), [Sentry ownership](https://docs.sentry.io/product/issues/ownership-rules/), [Sentry suspect commits](https://docs.sentry.io/product/issues/suspect-commits/), [Chronosphere join keys](https://chronosphere.io/learn/exemplars-for-distributed-traces-a-better-approach-to-linking-metrics/).
*Applies here:* once a Jira component or PagerDuty service is known, Slack channel, Chronosphere label matcher, logz index and repo are lookups; only the residue needs fuzzy extraction. *Limits:* someone must build/refresh the table; stale catalogs are silent.

### P8. Fixed check catalog keyed on (labels, time window)
Once a start object resolves to service labels and an incident window, run a fixed set of parallel deterministic checks with per-check interestingness thresholds instead of free exploration. Grafana Sift: error-pattern logs (filter error-level, group into patterns, count ≥5, rate up vs pre-window baseline, 3 examples), HTTP error series, recent deployments, slow requests; window inherited from the incident. RCACopilot describes per-alert-type handlers that collected diagnostics in production before any LLM was added (deployment duration and summary length not re-verified). PagerDuty Related Incidents combine time proximity with service dependencies; the exact window is not stated in the linked page, so treat any specific minute count as a hypothesis. Blueprint First shows the execution shape: typed parse nodes, numeric conditionals (`old_gen_usage > 0.9`), fork/correlate joins, preconditions on expensive calls, LLM at two bounded nodes only.
*Sources:* [Sift analyses](https://grafana.com/docs/grafana-cloud/machine-learning/sift/analyses/), [Sift error-pattern logs](https://grafana.com/docs/grafana-cloud/machine-learning/sift/analyses/error-pattern-logs/), [RCACopilot 2305.15778](https://arxiv.org/abs/2305.15778), [PagerDuty related incidents](https://support.pagerduty.com/main/docs/related-incidents), [Blueprint First 2508.02721](https://arxiv.org/html/2508.02721), [Traversal causal indexer](https://www.traversal.com/blog/blog-causal-indexer-agentic-incident-root-cause-analysis-without-tokenmaxxing) (pattern+count+baseline compression before any model), [Meta](https://engineering.fb.com/2024/06/24/data-infrastructure/leveraging-ai-for-efficient-incident-response/) (ownership + code graph + time window narrows thousands of diffs to hundreds deterministically).
*Applies here:* chronosphere (PromQL error-rate/latency series; `get_log_histogram` as a near-free existence check before paying for rows), logz (error-pattern vs baseline via Drain3), arc/git (commits touching the service in window). *Limits:* Sift's algorithms are closed; only the leaf-check shape transfers.

### P9. Source-as-schema log-template navigation
Use the code as the schema for logs: one AST pass over logger calls turns each format string into a regex template with variable names/types and file:line; runtime lines are matched via a reverse index over constant tokens, then regex-verified ("pick the highest-ranked result that allows a regular expression match to succeed"); parse failure 0.12% on 24M HDFS lines. Identifier discovery is heuristic: a template variable is an ID if reported many times, with many distinct values, across multiple message types. ast-grep does the harvesting today (`logger.$METHOD($FMT, $$$)`, `--json` with metavariables and byte ranges, wasm build for the browser); Python `parse` inverts `format()` strings. Check OTel `code.file.path`/`code.line.number` first: if logz records carry caller fields, this collapses to a field read.
*Sources:* [Xu et al. SOSP 2009](https://www.sigops.org/s/conferences/sosp/2009/papers/xu-sosp09.pdf), [ast-grep](https://github.com/ast-grep/ast-grep), [parse](https://pypi.org/project/parse/), [OTel code.* semconv](https://opentelemetry.io/docs/specs/semconv/general/logs/), [logtrail-tools](https://github.com/sivasamyk/logtrail-tools) (only small OSS implementation, Java/slf4j).
*Applies here:* logz line → file:line → owning module/team → Slack channel; template variable bindings are the typed IDs to pivot on. *Limits:* needs source for the emitting code; tree-sitter gives names not types, so Java-style `toString` expansion must be approximated; templates are per release.

### P10. Def/ref graph + personalized PageRank + search cascade
Precompute at repo sync a name-level def/ref graph from tree-sitter `tags.scm` (aider: edges referencer→definer, weighted by reference count, boosted for long snake/camel identifiers and identifiers mentioned in the chat, and penalised for identifiers defined in many files; see `repomap.py` for the exact constants), seed the personalization vector with identifiers extracted from the ticket/log line, and rank files/symbols with no LLM. LocAgent's three tools are the minimal API: SearchEntity cascade (exact id → name dict → stemmed BM25 → rapidfuzz `token_set_ratio`), TraverseGraph (typed k-hop BFS over contains/imports/invokes/inherits), RetrieveEntity; ablation shows keyword/BM25 entry search is load-bearing (71.5→53.3 without it) and multi-hop traversal secondary. For type-resolved references, ship a SCIP index converted to SQLite (`scip expt-convert`: `global_symbols`, `mentions(symbol, role)`, `defn_enclosing_ranges`) loadable via sql.js. `git grep -n --column -e id1 --or -e id2` returns file/line/column spans, the code-side equivalent of ES highlight ([git grep](https://git-scm.com/docs/git-grep)).
*Sources:* [aider repomap blog](https://aider.chat/2023/10/22/repomap.html) / [repomap.py](https://github.com/Aider-AI/aider/blob/main/aider/repomap.py), [RepoMapper](https://github.com/pdavis68/RepoMapper), [LocAgent 2503.09089](https://arxiv.org/html/2503.09089), [SCIP CLI](https://github.com/sourcegraph/scip/blob/main/docs/CLI.md), [ctags JSON](https://docs.ctags.io/en/latest/man/ctags-json-output.5.html), [ripgrep --json](https://manpages.debian.org/testing/ripgrep/rg.1.en.html), [grep-ast](https://github.com/Aider-AI/grep-ast), [infigraph](https://github.com/intuit/infigraph) / [codebase-memory 2603.27277](https://arxiv.org/html/2603.27277v1) (embedded Cypher graphs, heavier).
*Applies here:* replaces the read/glob/grep/ast-grep loop; the identifier-worthiness multipliers are the agent's "which substring to grep" judgment made explicit. *Limits:* name-based only outside SCIP; SCIP indexers need a buildable checkout.

### P11. Lazy typed adapters / in-process graph query engine
If you want the "graph database" to be literal, Trustfall gives a GraphQL-like schema (vertex types, typed edges, parameterised root edges like `JiraIssue(key: String!)`, `SlackSearch(query: String!)`), four adapter functions per data source, lazy per-vertex neighbour resolution (tool called only when the query pulls that edge), and directives (`@filter` with regex ops, `@optional`, `@fold`/`@transform(count)`, `@recurse(depth)`, `@tag`) that stand in for the agent's fuzziness; it compiles to WASM and runs in the browser. Maltego's transform model (typed entity in → typed entities out; UI shows only transforms applicable to the selected type; "Machines" chain them) is the matching interaction design. Transposit built exactly this product (SQL joins across SaaS APIs for on-call) and has shut down, with its technology licensed to Harness; no reusable code or spec survives publicly, so it is a design precedent only ([Transposit](https://www.transposit.com/)).
*Sources:* [Trustfall](https://github.com/obi1kenobi/trustfall) / [BasicAdapter](https://docs.rs/trustfall_core/latest/trustfall_core/interpreter/basic_adapter/trait.BasicAdapter.html) (production in cargo-semver-checks), [Maltego](https://docs.maltego.com/en/support/solutions/articles/15000053545-building-integrations-for-maltego), [Steampipe KeyColumns](https://steampipe.io/docs/develop/writing-plugins), [MuleSoft patent](https://patents.google.com/patent/US10776189B2/en) (prior art; warns the hard part is relationship inference, not execution), [Transposit](https://www.transposit.com/).
*Applies here:* one adapter per MCP server; a saved investigation is one Trustfall query. *Limits:* real adapter code per server (Rust/Python/WASM), no string-extraction directive, one tool call per vertex on fan-out unless batched.

### P12. Programming-by-example position synthesis from (text, span) traces (no LLM at synthesis or runtime)
The recorded trace already has the shape classical PBE needs: `(text, [start,end])`. **FlashExtract**'s text DSL describes a span as `Pair(Pos(start), Pos(end))` where `Pos = AbsPos(k)` or `RegPos((r1,r2),k)`, "the k-th position whose left side matches regex r1 and right side matches r2" (k<0 counts from the right), with regexes of ≤3 tokens drawn from ~30 character classes plus *dynamic tokens*, literals mined from text near the highlighted spans (`"trace_id:"`, `"pod="`, `"PROJ-"`). Learning is per-operator witness functions plus version-space intersection across examples; negatives are enforced (`Y' ∩ P(σ) = ∅`); `CleanUp` drops any program whose output set is a superset of a retained program's; `Merge` is the disjunction for heterogeneous formats. It needed 2.36–2.86 examples per field on 75 real documents at ~0.8 s ([FlashExtract](https://www.microsoft.com/en-us/research/wp-content/uploads/2016/12/pldi14-flashextract.pdf)); FlashFill supplies the original position expressions, the DAG version space and the ranking heuristics (regex positions over constants, fewer tokens, smaller |k|) ([FlashFill](https://www.microsoft.com/en-us/research/wp-content/uploads/2016/12/popl11-synthesis.pdf)). **STALKER** gives the second deterministic rule language: linear landmark automata `SkipTo(l1) SkipTo(l2)` with wildcards (Number, Punctuation, HtmlTag, Anything), start/end rules learned separately by sequential covering (shortest uncovered example seeds a rule; one disjunct per source format), hierarchical extraction (parent region first, then value); it "requires no more than 9 examples for any rule" and learns perfect rules from a single example for more than half of them ([STALKER](https://usc-isi-i2.github.io/papers/muslea01-jaamas.pdf)). **Snowball/DIPRE** give the fuzzy fallback: weighted left/middle/right term-vector contexts around each chosen span, clustered into pattern centroids; a candidate matches a pattern by inner product above a threshold; pattern confidence = selectivity ([Snowball](https://www.cs.columbia.edu/~gravano/Papers/2000/dl00.pdf)). Kushmerick's LR/HLRT delimiter wrappers (longest literal left/right context shared by all examples) are the trivial baseline that Sumo Logic's `| parse "user=*: severity=*:"` anchor operator and Power Query's "Text between Delimiters" ship in production ([Kushmerick](https://doi.org/10.1016/s0004-3702(99)00100-9), [survey](http://staff.csie.ncu.edu.tw/chia/pub/iesurvey2006.pdf), [Sumo Logic](https://www.sumologic.com/help/docs/search/search-query-language/parse-operators/parse-predictable-patterns-using-an-anchor/), [Power Query](https://learn.microsoft.com/en-us/power-query/column-from-example)). RoadRunner infers a template and its variable slots from two results of the same class with no labels at all, useful for templated MCP outputs ([RoadRunner](http://www.vldb.org/conf/2001/P109.pdf)).

*Recipe (all in-process, no model):* (A) for each trace, enumerate start/end programs `{AbsPos(k)} ∪ {RegPos((r1,r2),k)}` with r1/r2 built from ≤3 tokens of the text around the span and k = rank of that (r1,r2) match from left or right; intersect candidate sets across all traces for the same (source tool, target tool, param); take negatives for free from every other value-shaped substring in the same text that the agent did not choose; rank survivors (RegPos > AbsPos, dynamic literal > generic class, fewer tokens, smaller |k|, CleanUp by subsumption); validate on held-out traces; if nothing survives, split by detected source format (Slack vs log vs wiki) and synthesise a `Merge` per format. (B) STALKER landmarks for the enclosing region first, then the value. (C) Snowball context vectors over typed-regex candidates as the ranker when exact tokens fail (typos, aliases, extra commas). (D) grex for value-shape candidates, (E) Drain3 slots for log lines so "which substring" becomes "which slot", (F) RegexGenerator (Java, GPL-3; input is literally text + highlighted spans, unhighlighted text as negatives) run offline once per extractor when you have tens of spans ([RegexGenerator](https://github.com/MaLeLabTs/RegexGenerator)). With thousands of traces, replay them in the order that maximises disagreement among surviving programs and consult a human/LLM only there ([significant inputs](https://arxiv.org/abs/2006.12638)).

*Availability:* the only polished FlashExtract engine is the PROSE SDK, .NET-only, non-commercial-use only, and frozen since October 2025 ([NuGet](https://www.nuget.org/packages/Microsoft.ProgramSynthesis.Extraction.Text/), [microsoft/prose samples](https://github.com/microsoft/prose)); the PyPI `prose-codeaccelerator` package is a dependency-confusion placeholder ([libraries.io](https://libraries.io/pypi/prose-codeaccelerator)); STALKER has no public code; no open-source FlashExtract reimplementation in Python/JS was found, so the papers are the implementation spec. Regel (MIT; Python + Java SEMPRE + Z3) and RFixer (Java + Z3; no LICENSE file found) synthesise/repair *whole-string* regexes from positive/negative strings and can run once offline ([Regel](https://github.com/utopia-group/regel), [RFixer](https://github.com/rongpan/RFixer)); AlphaRegex is educational-scale ([AlphaRegex](https://github.com/kupl/AlphaRegexPublic)).
*Where it fails vs LLM-written regex (Regexulator/DeepParse):* PBE needs one program consistent with *all* traces, so when the agent chose by meaning (the service named in the ticket title rather than in the stack trace) with no lexical cue, the version space empties or overfits to one disjunct per trace; one inconsistent trace kills synthesis, so cluster/dedupe traces and drop outliers first (as FlashFill does for noisy inputs); exact-token DSLs cannot absorb typos/aliases (only (C) or a normalisation table can); composing a free-text search query is a *transformation*, which FlashFill `Concat(SubStr, const)` covers only for fixed templates; and Regel's 26% PBE-only solve rate is the honest ceiling for examples alone ([Regel](https://arxiv.org/abs/1908.03316)).
*Applies here:* every "copied from unstructured text" binding from P1/TraceCompiler goes through (A)/(B) first, then (C), then the LLM loop of P2. *Limits:* re-implementation effort; licensing of the existing engines; no help for semantic selection.

### P13. Reuse a declarative "extract from response, feed the next request" DSL instead of inventing one
Several mature DSLs already ship the semantics the draft proposed to hand-roll. **Airbyte's low-code manifest** is the only surveyed format with all seven properties (regex capture, array fan-out, branching, time windows, pagination, secrets, embeddable runtime): `SubstreamPartitionRouter` with `parent_key`/`partition_field`/`extra_fields` fans a child stream out over each parent record (records missing `parent_key` are skipped), `DpathExtractor` + `RecordFilter` + `AddFields` select and derive fields, the Jinja environment ships `regex_search`/`regex_replace` filters and `format_datetime`/`day_delta`/`duration`/`now_utc` macros, `DatetimeBasedCursor` exposes `stream_interval` with `step`/`lookback_window`, `DefaultPaginator` and `DefaultErrorHandler`/`HttpResponseFilter`/`WaitTimeFromHeader` handle paging and 429s, and `ManifestDeclarativeSource` / PyAirbyte `get_source(source_manifest=…)` run it in-process with optional local DuckDB ([partition router](https://docs.airbyte.com/platform/connector-development/config-based/understanding-the-yaml-file/partition-router), [filters.py](https://raw.githubusercontent.com/airbytehq/airbyte-python-cdk/main/airbyte_cdk/sources/declarative/interpolation/filters.py), [macros.py](https://raw.githubusercontent.com/airbytehq/airbyte-python-cdk/main/airbyte_cdk/sources/declarative/interpolation/macros.py), [component schema](https://raw.githubusercontent.com/airbytehq/airbyte-python-cdk/main/airbyte_cdk/sources/declarative/declarative_component_schema.yaml), [PyAirbyte](https://airbytehq.github.io/PyAirbyte/airbyte.html), [overview](https://docs.airbyte.com/platform/connector-development/config-based/low-code-cdk-overview)). Caveat: HTTP-only and batch-oriented, so MCP tools need a ~50-line local HTTP shim (`POST http://127.0.0.1:8787/call/{server}/{tool}`) or a `CustomDecoder` that parses `result.content[0].text`. **Hurl**'s capture grammar (`name: jsonpath "$.x" regex /(…)/ nth 0 toDate "%+" dateFormat "%Y-%m-%d"`) is the best per-field extractor micro-language: query + chainable filters, including a `jsonpath` *filter* that parses JSON embedded in a string (exactly the MCP `content[0].text` shape); it is a Rust crate (`hurl::runner::run` with a `VariableSet`) with `--secret` redaction and retries but no loops or branches, so use it as extractor syntax, not orchestrator ([Hurl captures](https://hurl.dev/docs/capturing-response.html), [filters](https://hurl.dev/docs/filters.html), [lib](https://docs.rs/hurl/latest/hurl/runner/fn.run.html)). **Step CI** YAML (captures via jsonpath/regex/xpath/header, `if:` Filtrex conditions, env/secrets, retries) via `@stepci/runner` is the closest ready-made Node interpreter, missing only fan-out ([Step CI](https://docs.stepci.com/reference/workflow-syntax.html), [runner](https://raw.githubusercontent.com/stepci/runner/main/README.md)). **Flowpipe** (single Go binary) already implements the orchestrator: HCL pipelines with `for_each`, `if`, `loop { until }`, `retry`, `error { ignore }`, `max_concurrency`, an `http` step that auto-decodes JSON, with hub mods for Slack/Jira/PagerDuty; the `regex`/`regexall`/`timeadd` functions are standard HCL/cty but were not confirmed in Flowpipe's function reference ([Flowpipe steps](https://flowpipe.io/docs/flowpipe-hcl/step/index), [http step](https://flowpipe.io/docs/flowpipe-hcl/step/http)). Worth borrowing from without adopting: Windmill's OpenFlow JSON (`forloopflow`, `branchone`/`branchall`, `input_transforms`) as the cleanest published DAG schema, but its runtime needs a server ([OpenFlow](https://www.windmill.dev/docs/openflow), [branches](https://www.windmill.dev/docs/flows/flow_branches)); dlt's `rest_api` config with `resolve` parent-child params, paginators and `response_actions` (regex needs a Python `map`) ([dlt rest_api](https://dlthub.com/docs/dlt-ecosystem/verified-sources/rest_api/basic), [resources](https://dlthub.com/docs/general-usage/resource)); Meltano's `get_child_context` for state partitioning per parent key ([Meltano](https://sdk.meltano.com/en/latest/parent_streams.html)); Tavern's `validate_regex` named groups ([Tavern](https://tavern.readthedocs.io/en/latest/basics/)); n8n's `extractEmail()`/`extractUrl()`/`extractDomain()` string helpers ([n8n](https://docs.n8n.io/build/work-with-data/transform-data/expression-reference/string.md)); and JSONata's regex literals, `$match` with `{match,start,end,groups}` and predicate filters, if you want one browser-runnable expression language for the `extract:` field ([JSONata](https://docs.jsonata.org/regex)). Keep Arazzo's naming (`$steps.<id>.outputs.<name>`, `$inputs`, `successCriteria`, `onFailure: retry`) so files stay convertible to Arazzo tooling ([Arazzo README](https://raw.githubusercontent.com/OAI/Arazzo-Specification/main/README.md), [Redocly Respect](https://redocly.com/docs/respect)).
*Sources:* as linked above; also [Karate](https://raw.githubusercontent.com/karatelabs/karate/v1.4.1/README.md) (JVM, Gherkin+JS; functionally complete but a poor fit), [Singer spec](https://github.com/singer-io/getting-started/blob/master/docs/SPEC.md) / [tap-rest-api-msdk](https://raw.githubusercontent.com/Widen/tap-rest-api-msdk/main/README.md) (no declarative parent/child), [k6](https://grafana.com/docs/k6/latest/using-k6/scenarios/) (plain JS, not recommended).
*Applies here:* a Jira→Slack→Logz chain in Airbyte terms is three streams: `jira_issue` (POST `/jira/get_issue`, `AddFields error_sig: "{{ record['fields']['description'] | regex_search('(?m)^(?:Error|Exception):\\s*(.+)$') }}"`, `day: "{{ format_datetime(record['fields']['created'], '%Y-%m-%d') }}"`), `slack_hits` (SubstreamPartitionRouter on `error_sig` with `extra_fields [[day],[service]]`, body `query: "\"{{ stream_slice['error_sig'] }}\" in:#incidents after:{{ stream_slice.extra_fields['day'] }}"`, PageIncrement paginator, `AddFields trace_id: … regex_search('trace[_-]?id[=: ]+([0-9a-f]{16,32})')`, `record_filter condition "{{ record['trace_id'] }}"`), and `logz_lines` (partitioned on `trace_id`, `DatetimeBasedCursor` on `@timestamp` with `step PT4H`/`lookback_window PT1H`, body `query: "\"…error_sig…\" AND trace_id:{{ stream_slice['trace_id'] }}"`, `from/to` from `stream_interval`). *Limits:* the shim; Airbyte's sync model is per-config, so per-ticket runs are driven by config values; Hurl/Step CI cannot iterate (re-run the tail per item).

### P14. Backend-native precision ladder, highlight-based span localisation, and per-backend caps
Much of the agent's "phrase the search" fuzziness can be delegated to the backend as a fixed ladder generated from extracted IDs/keyphrases plus a time window: exact phrase → AND of tokens → OR of tokens → prefix/wildcard → edit-distance fuzzy. Only Elasticsearch (and Confluence CQL's Lucene `~`) offer true edit-distance fuzziness; the rest need alternation regex or client-side matching.
- **Slack**: `"exact phrase"`, `-term`, `in:#chan`, `from:@u`, `has:`, `is:thread`, `before:/after:/on:` (day granularity only), `during:`, trailing `*` (≥3 chars); no fuzziness ([Slack search](https://slack.com/help/articles/202528808-Search-in-Slack)). `search.messages`: `count` max 100, `page` max 100 (so ≤10,000 results), Tier 2 (~20/min), `highlight=true` wraps matches in U+E000/U+E001 ([search.messages](https://docs.slack.dev/reference/methods/search.messages)). korotovsky's MCP `conversations_search_messages` takes `search_query` plus `filter_in_channel`/`filter_users_from`/`filter_date_before|after|on|during`/`filter_threads_only`, `limit`, page-counter `cursor`; it appends filters as Slack modifiers, hard-codes `highlight=false`, returns CSV, and needs a user token ([korotovsky](https://github.com/korotovsky/slack-mcp-server), [handler](https://raw.githubusercontent.com/korotovsky/slack-mcp-server/master/pkg/handler/conversations.go)), so span localisation must be done locally. `conversations.history`: `limit` max 999, Tier 3; new non-Marketplace apps since 2025-05-29 get 1 req/min and 15 objects ([conversations.history](https://docs.slack.dev/reference/methods/conversations.history)). Whether bare terms are ANDed or ORed was not confirmed; issue one call per token if OR semantics are needed (hypothesis).
- **Confluence CQL**: `~` on `text`/`title`/`space.title` accepts Lucene syntax (`*`, `?`, `word~` fuzzy, phrases), `ancestor`, `space`, `label`, `lastModified >= now("-30d")`, `ORDER BY`; ladder `title ~ "<phrase>" OR text ~ "<phrase>"` → `text ~ "tok1 tok2"` → `text ~ "tok1~ tok2~"` → `text ~ "prefix*"`, phrase-quoting hyphenated keys ([CQL](https://developer.atlassian.com/cloud/confluence/advanced-searching-using-cql/), [fields](https://developer.atlassian.com/cloud/confluence/cql-fields/)). REST `/wiki/rest/api/search` has cursor pagination, `limit` forced to 25 when bodies are expanded, and an `excerpt` parameter that can return highlighted excerpts (allowed values and marker format not confirmed on the fetched page) ([search API](https://developer.atlassian.com/cloud/confluence/rest/v1/api-group-search/)). sooperset/mcp-atlassian wraps non-CQL queries as `siteSearch ~ "q"` with `text ~` fallback and caps at 50, a copyable heuristic ([mcp-atlassian](https://mcp-atlassian.soomiles.com/docs/tools/confluence-search.md)).
- **Jira JQL**: `~` supports trailing `*`, escaped phrases, OR-by-default inside the string, AND/NOT/`+`/`-`, stemming; fuzzy `~`, proximity and boost are explicitly *ignored* ([text search](https://support.atlassian.com/jira-software-cloud/docs/search-syntax-for-text-fields/)). Structural windows via `updated >= -14d`, `status CHANGED TO Done DURING ("-2d", now())`, `WAS` ([operators](https://support.atlassian.com/jira-software-cloud/docs/jql-operators/)). REST rate limits (1 point per read, 100 GET/s burst, hourly quotas) are not the binding constraint; **Rovo credits** are: 25/70/150 credits per user per month on Jira and Confluence plans, 1–10 credits per MCP call, semantic `search` and `getTeamworkGraphContext` up to 10 credits ([rate limiting](https://developer.atlassian.com/cloud/jira/platform/rate-limiting/), [Rovo limits](https://support.atlassian.com/rovo/docs/rovo-usage-limits/), [Rovo tools](https://support.atlassian.com/atlassian-ai-gateway/docs/supported-tools/)). Keep templates on `searchJiraIssuesUsingJql`/`searchConfluence`; per-tool parameter names must be read from the live `tools/list` because Atlassian does not publish them.
- **Elasticsearch / Logz.io**: `query_string` encodes the whole ladder in one string with ranking (`"exact phrase"^4 OR (tok1 AND tok2)^2 OR tok1~1 OR prefix*`, `minimum_should_match`; escape `+ - = && || > < ! ( ) { } [ ] ^ " ~ * ? : \ /`) but throws on bad syntax; `simple_query_string` never errors and `flags` can restrict operators, so prefer it for machine-built queries from messy substrings ([query_string](https://www.elastic.co/docs/reference/query-languages/query-dsl/query-dsl-query-string-query), [simple_query_string](https://www.elastic.co/docs/reference/query-languages/query-dsl/query-dsl-simple-query-string-query)). `fuzziness: AUTO` = exact for 0–2 chars, 1 edit for 3–5, 2 edits above ([common options](https://www.elastic.co/docs/reference/elasticsearch/rest-apis/common-options)); `multi_match` fuzziness only on best_fields/most_fields/bool_prefix ([multi_match](https://www.elastic.co/docs/reference/query-languages/query-dsl/query-dsl-multi-match-query)); `match_phrase_prefix`'s 50-term expansion is unreliable on high-cardinality IDs ([phrase_prefix](https://www.elastic.co/docs/reference/query-languages/query-dsl/query-dsl-match-query-phrase-prefix)); `wildcard` with `case_insensitive` on keyword fields ([wildcard](https://www.elastic.co/docs/reference/query-languages/query-dsl/query-dsl-wildcard-query)). `highlight` with custom `pre_tags`/`post_tags` and `number_of_fragments: 0` returns the whole field with markers, which is the LLM-free way to localise the span for the next hop ([highlighting](https://www.elastic.co/guide/en/elasticsearch/reference/8.17/highlighting.html)). **Logz.io** `/v1/search`: full DSL incl. `highlight`, `size` max 10,000 (1,000 with aggregations), *no fuzzy expansions and no leading wildcards*, default range = last 2 calendar days unless `dayOffset` or a timestamp filter is given, 100 concurrent requests/account ([search](https://api-docs.logz.io/docs/logz/search/), [API](https://api-docs.logz.io/docs/logz/logz-io-api/)); `/v1/scroll` 1,000/page, ≤2 consecutive daily indexes, so longer windows split into day-pair scrolls ([scroll](https://api-docs.logz.io/docs/logz/scroll/)). No official Logz.io MCP repo was found; the unofficial one exposes a Lucene passthrough plus a coarse `timeRange` enum and `limit` ≤1000 ([jklnr](https://github.com/jklnr/logzio-mcp-server)). Always send an explicit `@timestamp` range from the previous hop.
- **Prometheus / Loki / Chronosphere / Grafana MCP**: PromQL matchers are RE2 and fully anchored, so wrap fuzzy names as `.*name.*` or resolve them first via label-value listing; range results ~11,000 points ([PromQL](https://prometheus.io/docs/prometheus/latest/querying/basics/)). LogQL: anchored stream selectors, unanchored line filters `|= "phrase"` then `|~ "(?i)(id1|id2|id3)"`, then `| json | traceID="…"` ([LogQL](https://grafana.com/docs/loki/latest/query/log_queries/)); `query_range` `limit` default 100, RFC3339 or epoch, `since` ([Loki API](https://grafana.com/docs/loki/latest/reference/loki-http-api/)). Grafana MCP `query_loki_logs(limit default 100)`, `query_prometheus(step_seconds, now-1h)`, `list_prometheus_metric_names(regex)`, `list_loki_label_values(matchers)`, Sift `find_error_pattern_logs`; set the Loki limit one below the server cap to detect truncation ([mcp-grafana](https://github.com/grafana/mcp-grafana)). Chronosphere MCP: `query_logs_range(query, time_range, limit, page_token)` returning `logID` per hit so `get_log` fetches full lines only for matches, `get_log_histogram` (100 buckets) as a cheap existence check, `list_log_field_values`, `query_prometheus_range(step 60, limit 100 series)`, `list_traces(service|operation|trace_ids)`, times as `now-2h`/RFC3339 ([logs.go](https://raw.githubusercontent.com/chronosphereio/chronosphere-mcp/main/mcp-server/pkg/tools/logs/logs.go), [tools.go](https://raw.githubusercontent.com/chronosphereio/chronosphere-mcp/main/mcp-server/pkg/tools/prometheus/tools.go)). Chronosphere log syntax: `KEY : VALUE` is substring, `=~` is RE2 on the first 1,024 chars, bare quoted string is full-text, pipes `summarize`/`parse`/`top-nested`; recipe `service="<svc>" AND ("<phrase>" OR message:"id1" OR message:"id2")` → `message=~"(?i)(id1|id2|prefix.*)"` ([syntax](https://docs.chronosphere.io/investigate/querying/query-logs/query-syntax.md)).
- **PagerDuty**: no free-text search at all; `list_incidents` takes `status[]`, `since/until`, `service_ids`, `teams_ids`, `urgencies`, `limit` (REST caps 100/page; MCP model 1–1000 with a warning at 1000), `sort_by`; the OSS server is archived in favour of the hosted `mcp.pagerduty.com` ([incidents.py](https://raw.githubusercontent.com/PagerDuty/pagerduty-mcp-server/main/pagerduty_mcp/models/incidents.py), [OpenAPI](https://raw.githubusercontent.com/PagerDuty/api-schema/main/reference/REST/openapiv3.json)). Match phrases locally over titles/alert bodies.
- **Google Drive**: `fullText contains` matches whole tokens only (phrase when double-quoted), `name contains` is prefix-of-word only, `modifiedTime > 'RFC3339'`, no wildcard/fuzzy; `pageSize` max 1000, `includeItemsFromAllDrives`, check `incompleteSearch`; 325k quota units/user/min ([search terms](https://developers.google.com/workspace/drive/api/guides/ref-search-terms), [files.list](https://developers.google.com/workspace/drive/api/reference/rest/v3/files/list), [limits](https://developers.google.com/workspace/drive/api/guides/limits)). The archived reference gdrive MCP exposes only `search(query)` (per its README; wrapping as `fullText contains` with pageSize 10 is from prior knowledge) ([gdrive README](https://raw.githubusercontent.com/modelcontextprotocol/servers-archived/main/src/gdrive/README.md)).
- **gcloud / Azure**: `listLogEntries(resourceNames[], filter, orderBy default asc, pageSize 50)` takes a raw Cloud Logging filter ([logging tools](https://raw.githubusercontent.com/googleapis/gcloud-mcp/main/packages/observability-mcp/src/tools/logging/logging_api_tools.ts), [gcloud-mcp](https://github.com/googleapis/gcloud-mcp)); the grammar has `:` substring, `=~` regex, bare-quoted global terms, `SEARCH()`, RFC3339 `timestamp`, 20,000-char queries (so hundreds of IDs can be ORed) ([Cloud Logging](https://docs.cloud.google.com/logging/docs/view/logging-query-language)). Azure MCP monitor tools take KQL plus `Hours`/`Limit`; `has_any`/`contains`/`matches regex` cover the ladder ([Azure MCP](https://learn.microsoft.com/en-us/azure/developer/azure-mcp-server/tools/azure-monitor)).
- **git**: `git log --since/--until -i -E --grep=… --all-match -n 50 --format=…`, `-S`/`-G` pickaxe with `--pickaxe-regex`, `-F` for unescaped extracted strings ([git log](https://git-scm.com/docs/git-log)); `git grep -n --column -e a --or -e b` for spans ([git grep](https://git-scm.com/docs/git-grep)). The reference git MCP exposes only time-bounded `git_log(max_count 10)` and no grep/pickaxe, so message matching must be local or a thin custom tool must shell out ([git MCP](https://raw.githubusercontent.com/modelcontextprotocol/servers/main/src/git/README.md)).
*Applies here:* P4 templates emit the ladder per backend with the window inherited from the incident; the planner reads highlights (ES/Logz, Confluence, git grep) where available and re-scans locally (Slack, PagerDuty, Drive, gcloud) otherwise. *Limits:* Rovo per-tool schemas, official Logz.io MCP, PagerDuty rate limits and Jira enhanced-search paging details are undocumented or unverified (see §7).

| Sub-behaviour | Best non-LLM substitute | Quality |
|---|---|---|
| **Tool selection ("which server next")** | Signature-triggered templates from traces (P1) for known incident types; korrel8r-style goal/neighbourhood search over the class graph with skip-on-blank rules, or an Apollo-federation-style planner over `(type, key, resolver-tool)` triples (P4) for exploration; entity-type-filtered transform menus (P11) for humans | **Mostly.** The paper evidence (45% deterministic share; RCACopilot handlers) says the common paths are enumerable. Novel incidents still route to the agent tier. |
| **ID extraction from long strings** | Structured fields first (Jira/PagerDuty JSON, OTel `code.*`, Chronosphere `logID`); then typed mask catalog via Drain3 for machine text, gazetteer + synthesised regexes for prose, Cortex-style recursive walk of nested JSON (P3, P9) | **Fully** for ID-shaped values (keys, SHAs, UUIDs, pods, timestamps, catalog names). **Poorly** for semantic values (which customer, which of three error messages matters): DocILE regex roughly 10–20% on names/amounts. |
| **Choosing *which* substring when several candidates exist** | FlashExtract `RegPos((r1,r2),k)` / STALKER landmark programs synthesised from `(text, span)` traces with negatives taken from unchosen candidates (P12); Snowball context-vector ranking as fuzzy fallback; Drain3 slot index per template; backend highlights (ES/Logz `highlight`, `git grep --column`) to narrow the candidate set (P14); Xu's identifier heuristics and aider's long-identifier boost as priors | **Mostly**, deterministically, when a lexical cue (left/right context, ordinal, enclosing field) explains the agent's choice: FlashExtract needed 2.4–2.9 examples per field, STALKER ≤9 and often 1. **Poorly** when the choice was by meaning with no lexical cue; the version space empties and this residue goes to the bounded LLM call. Validate every learned program on held-out traces. |
| **Query phrasing for structured params** (JQL, CQL, PromQL, ES DSL, LogQL, KQL, Cloud Logging) | Templates with `{$steps.x.outputs.y}` slots (Arazzo/Keep/korrel8r/Airbyte); emit full DSL with the per-backend precision ladder and exact label matchers (P14); resolve fuzzy service names to exact label values via list-label-values first; time window inherited from the incident in the backend's own encoding | **Fully**, and often more precise than the agent (exhaustive paging, explicit `@timestamp` ranges that avoid Logz.io's 2-day default, exact term filters). |
| **Query phrasing for free-text params** (Slack `search_query`, Confluence `search`, gdrive `search_files`) | Identifier-first (any extracted ID beats prose); the backend ladder: exact phrase → AND → OR → prefix (Slack `*`, CQL `~`/`*`, Drive whole-token `fullText contains`); Confluence `siteSearch ~` for backend relevance ranking; YAKE keyphrases filtered by corpus IDF over your own cache; keyqueries fitted from traces (which keyphrase subsets retrieve the item the agent used); synonym/alias table mined from traces as a click log | **Mostly** when an ID or catalog name is present; **poorly** for pure paraphrase from ticket prose. Sources: [keyqueries](https://downloads.webis.de/publications/papers/hagen_2016b.pdf), [YAKE](https://github.com/LIAAD/yake), [click-log synonym mining](https://www.semanticscholar.org/paper/Query-Rewriting-using-Automatic-Synonym-Extraction-Mandal-Khan/1346c1bdf3092fcc91af81a6f21abca4c99b5b05). |
| **Result filtering / ranking** | Local hybrid index with RRF + domain rerank rules fitted to traces (P6); Meta-style deterministic narrowing by ownership + code graph + time window; backend-side ranking via `query_string` boosts | **Mostly.** Semble's report suggests rerank heuristics recover most of the gap; the residual is semantic relevance ranking. |
| **Stopping / branching criteria** | Arazzo `successCriteria` (boolean/regex/JSONPath), Airbyte `RecordFilter`/`HttpResponseFilter`, Step CI `if:`, Grafana's "link only if all variables resolve", korrel8r skip-on-blank, Sift thresholds (count ≥5 and rate up), `isError` branching, Blueprint preconditions, Chronosphere/ES histogram or count checks before paying for rows | **Mostly.** Branch conditions the agent acted on are recoverable from traces (P1); "is this evidence sufficient" for a novel case is not. |
| **Summarisation / narrative** | Structured evidence map (korrel8r's correlation graph with hit counts; Sift's suggestions list; Blueprint's typed findings) rendered by the UI | **Poorly** as prose; **fully** as a structured evidence view. Both Blueprint First and RCACopilot keep exactly this as the LLM node. |

## 4. Recommended architecture sketch

**A. Trace recording (zero infra).** One Claude Code `PostToolUse` hook with matcher `mcp__.*` appending the hook payload (session id, tool name, tool input, tool response; verify the exact field names, including whether a prompt/tool-use id is present, against the hooks doc) to JSONL, joined to `transcript_path` for the model's reasoning between calls (the supervision signal for "why this substring") ([hooks](https://code.claude.com/docs/en/hooks)). Alternatively a protocol-level VCR proxy ([mcp-recorder](https://github.com/devhelmhq/mcp-recorder), [agent-vcr](https://github.com/Jarvis2021/agent-vcr)) or [fiberplane/mcp-gateway](https://github.com/fiberplane/mcp-gateway) (SQLite log of all traffic); cassettes double as offline fixtures so extractor development never hits Jira/Slack. Use `PreToolUse` + `updatedInput` to shadow-test a generated query generator against the model's own choice before removing the model. Record `discover` resolutions for Rovo's deferred tools.

**B. Trace → template induction (one-time, mostly LLM-free).** Group traces by trigger signature (PagerDuty alert type / Jira issue type / service). Apply TraceCompiler's binding taxonomy: for every argument of every call, search prior results for the value (exact, then `partial_ratio_alignment`); label constant / input / copied / transformed / unresolved. AWM's rule-based inducer (dedupe by action sequence, replace instance values with typed slots) needs no LLM. Serialise into an existing DSL rather than a new one (P13): the Airbyte manifest vocabulary (streams + `SubstreamPartitionRouter` + `AddFields` with `regex_search` + `DatetimeBasedCursor`) if the runtime is Python, or Step CI YAML via `@stepci/runner` with a thin fan-out wrapper if it is Node, or Flowpipe HCL if a Go binary is acceptable; keep Arazzo's `$steps.<id>.outputs.<name>` naming and `successCriteria`. Promotion counters and acceptance tests per P1.

**C. Extractor synthesis (PBE first, LLM second).** For each "copied from unstructured text" binding, build the `(text, span)` dataset automatically from traces, derive negatives from unchosen value-shaped substrings in the same text, dedupe/cluster noisy traces, and run the P12 synthesiser: LR delimiters → FlashExtract `RegPos((r1,r2),k)` with dynamic tokens → STALKER disjuncts per source format → Snowball context vectors. Validate on held-out traces; keep the program only when it reproduces the agent's span on all of them. Only for bindings whose version space empties, run a Regexulator-style FP/FN loop or DeepParse's list-of-typed-regexes contract against the Claude API, gated by ScrapingBee's three audits; keep a candidate list per (template, step). Store the registry in lnav/Mattermost-autolink shape: `{when, on_field, program_or_regex, named_groups, types, target_param_template}` in SQLite. Feed the typed regexes (grex-generated where the value set suffices) into Drain3 `masking_instructions` (persist the miner state to file) and dump catalogs via MCP into a FlashText/ahocorasick_rs gazetteer with alias dict; RapidFuzz with cutoff ~85–90 as fallback.

**D. Link graph + entity catalog.** Bootstrap rows by RESTler name-matching over every server's `inputSchema` (snapshot `tools/list --full` once; note which tools declare `outputSchema`). Confirm/prune with traces; the LLM writes the remaining rows as Grafana-correlation 5-tuples in the Apollo Connectors shape `(entity type, key fields, tool, argument mapping, output selection)`. Static hub table (P7) from Backstage/incident.io export, CODEOWNERS, and label-value dumps via the backends' list-label-values tools. Runtime: korrel8r-style class graph with template rules (Jinja/Nunjucks), skip-on-blank, `range` fan-out, goal/neighbourhood search, or a simplified federation planner (walk the requested selection; for each unresolved entity field find the tool whose key it can satisfy; batch representations); or Trustfall adapters if you want a real query language and browser-side WASM execution.

**E. Local index.** One SQLite file: `items` + external-content FTS5 (`unicode61 tokenchars '-_./:@'`, bm25 column weights) + FTS5 trigram + `vec0` (a Model2Vec static model, ideally distilled with a vocabulary that includes your service/alert names; check dimensions and licence on the model card; partitioned by `source`). Hash-based incremental reindex. RRF weights and rerank rules fitted so the trace's chosen item ranks first. In the browser: sqlite-wasm with sqlite-vec, or MiniSearch/Orama for a few thousand items.

**F. Codebase artefacts (per repo sync, static).** ast-grep YAML rules per logger idiom → log-template table (P9); tree-sitter tags → def/ref graph JSON + personalized PageRank ranker (P10); LocAgent-style search cascade (exact → name dict → bm25s → rapidfuzz); CODEOWNERS matcher; `git grep --column` and `git log -S/--grep` wrappers where the git MCP lacks them; optional SCIP→SQLite for type-resolved references where CI can build. Check OTel `code.*` fields in logz first.

**G. Check catalog and query ladders.** Sift-shaped parallel checks over (labels, window): logz error patterns vs pre-window baseline (Drain3 templates, count ≥5, ratio >1) with explicit `@timestamp` ranges and `highlight`, Chronosphere `get_log_histogram` then `query_logs_range` then `get_log` for matched IDs, PromQL error-rate/latency series with label values resolved first, arc/git commits in window, PagerDuty `list_incidents(since, until, service_ids)` and change events, executed as a Blueprint graph with fork/correlate joins and preconditions before expensive Confluence full-text or Rovo semantic `search` (10 credits) calls. Each backend's ladder from P14 is a fixed function `(ids, phrases, window) → query`, with fallbacks tried in order until hit count ≥1.

**H. Runtime, budgets and safety.** `mcpc` named sessions (or `toolscript` gateway) with `--json`; branch on `isError`; copy Inspector's exit-code classification; gate speculative fan-out on `readOnlyHint`; `tools-get --schema` drift check on startup; circuit breaker demotes a template to the agent tier on validation failure. Budget per investigation in *calls and credits*, not just tokens: Rovo credits (1–10 per call against 25–150/user/month), Slack Tier 2 (~20/min, 100×100 result cap), Logz.io 10,000 hits and 100 concurrent requests, Drive quota units, Loki/Chronosphere 100-row defaults; plus a token cap for the bounded LLM nodes (Cleric's 10¢–$1 framing).

**I. Frontend.** Inspector-shaped shell (schema-generated forms, native content rendering, local token-gated proxy, deep links pre-filling a tool call) extended with Maltego-style typed nodes whose menu lists applicable link rows, a korrel8r-style correlation map showing rendered goal queries with hit counts, and highlighted spans (from backend highlights or local re-scan) that the user can accept or re-select, each correction becoming a new `(text, span)` example for P12. Browser talks to `mcpc --proxy` or `mcpo` on localhost; tokens stay in the keychain.

## 5. Where an LLM is still needed (and the cheapest way)

1. **Extractor synthesis residue** — only for bindings where the P12 synthesiser finds no program consistent with all held-out traces (selection by meaning, no lexical cue). Then the Regexulator loop with a validation split, one-time per (template, step); Compiled AI's break-even is roughly 17 executions. Cache candidates; regenerate only on audit failure after non-LLM healing (difflib, RFixer-style repair from the new positive/negative values) fails.
2. **Pseudo-labelling when traces are few** — batch, one-time: N candidate extractors + majority vote + reflector repair (Tool-Making App. D; N=1 loses 8.6pp). With many traces, active selection of maximally-disagreeing traces limits how many need a label ([2006.12638](https://arxiv.org/abs/2006.12638)).
3. **Semantic field extraction** (customer name, "the interesting error", which of several services the thread is about) — a compile-time-fixed prompt + output schema + trigger condition (Compiled AI "Code Factory"), smallest model that passes the regression suite, invoked only on cache miss (LILAC pattern) ([LILAC](https://arxiv.org/abs/2310.01796)).
4. **Free-text query phrasing from pure prose** when no ID/catalog name is present — same bounded call, cached by ticket key; shadow-test against the deterministic ladder + keyphrase generator and drop the call where they agree; Rovo's semantic `search` is a non-LLM-in-your-loop alternative but costs 10 credits.
5. **Final narrative** — one or two bounded nodes at the end (Blueprint First and RCACopilot both keep the summary as the LLM node), fed the compressed evidence map, never raw telemetry.
6. **Novel-incident fallback** — the agent tier behind the circuit breaker; its traces become next month's templates.
7. **Not needed, despite appearances:** trace clustering by intent (static-embedding cosine suffices), embedding of results (static lookup), which-tool-next for known signatures, ID-shaped extraction, structured query generation, and, newly, most "which of N candidates" decisions.

## 6. Open questions / not found

- **No MCP cross-server linking convention.** We found no server emitting `resource_link` blocks with `jira://KEY`-style URIs and none declaring `structuredContent`/`outputSchema` among those we read (korotovsky Slack returns CSV; Chronosphere, PagerDuty, gcloud return JSON-as-text); this is absence of evidence, not a survey. `completion/complete` exists only for prompts/resource templates ([completion](https://modelcontextprotocol.io/specification/2025-06-18/server/utilities/completion)), so a thin in-house facade server is the only way to get protocol-level ID→resource resolution.
- **No tool that emits a workflow DAG from agent traces.** TraceCompiler and Progressive Crystallization describe the algorithm but ship no code; AWM/SkillWeaver/ASI ([2504.06821](https://arxiv.org/abs/2504.06821), [2504.07079](https://arxiv.org/abs/2504.07079)) keep an LLM at inference. The DSLs in P13 are targets for such a compiler, not compilers.
- **Context-dependent substring selection is solved only when a lexical cue exists** (P12); semantic selection remains LLM-bound, and Regel's 26% PBE-only figure bounds expectations for examples-only regex synthesis.
- **No open-source FlashExtract/STALKER implementation in Python/JS**; PROSE is .NET, non-commercial, frozen; RegexGenerator is GPL-3/JVM. Re-implementation from the papers is required.
- **No maintained library of ops-specific ID regexes** (Jira keys, k8s pods, trace ids); seed from grok/iocextract, grex over trace values, and let the LLM fill the rest.
- **Rovo deferred tools** mean a `tools/list` snapshot is insufficient; traces must capture `discover`. Per-tool parameter schemas and request rate limits are unpublished; only credit costs are.
- **Browser story is workable but not off-the-shelf:** Model2Vec browser packaging unverified; sqlite-vec in sqlite-wasm; CORS behaviour of remote vendor MCP servers unverified, so assume a local proxy.
- **Mechanism gaps in the strongest evidence:** Progressive Crystallization is a 4-page paper; Sift's grouping algorithm is closed; keyqueries' enumeration algorithm is in an unfetched companion paper; the eBay synonym paper was summarised from abstracts only.
- **Type resolution outside Python/Java** for P9/P10 depends on SCIP indexers needing buildable checkouts; the status of alternative tools (stack-graphs, PyCG, embeddable Semgrep) was not verified.
- **Dead ends:** HN threads on "MCP without LLM" were generic; semantic-cache products cache responses, not decisions-as-code; knowledge-graph MCP servers expose graph DBs via MCP rather than treating MCP servers as a graph; CompileAgent is a toy DSL runner; Alloy/AgentDistill/Trace2Skill distil into LLM-consumed artefacts; Transposit's SQL docs are gone.

## 7. Gaps that remain

The gap-fill research ran with an exhausted web-search budget, so it fetched known primary URLs only; the following critique gaps were not closed or were only partly closed.

- **Investigation-UI prior art (critique gap 4)** is still thin: only Transposit's shutdown notice was retrievable. Fiberplane notebooks, papermill/nurtch runbooks, Datasette and its plugins, Observable, Splunk workflow actions, Kibana/Datadog/Grafana drilldown URL templates, Shoreline, DevTools Recorder/Playwright codegen, and Nushell/jc/Miller/VisiData were not researched; section 4I remains a sketch.
- **Evaluation methodology and corpus-size guidance (gap 5)** is absent: no source here describes an offline replay benchmark (step-level argument agreement, evidence-set agreement, held-out splits) or how many traces were needed before templates stabilised beyond Progressive Crystallization's thresholds. Facts flagged by the critique that remain **unverified** and should be checked before implementation: FTS5 query-execution details and trigram limits; Semble's exact ablation numbers; PagerDuty Related Incidents' time window; RCACopilot's deployment duration and summary length; Blueprint First's acceptance rate; Claude Code hook payload field names; Inspector CLI exit codes; Model2Vec model sizes/dimensions/licences and any JS port; the Regexulator repo size and any Arazzo runner implementation (the Jentic runner URL 404'd); the `anthropics/oncall-kit` entry from the draft has been removed as unverifiable.
- **Practitioner and "LLM as compiler" community sources (gap 6)** were not searched: no post-mid-2026 trace-to-workflow compilers, SREcon/KubeCon talks, DSPy/TypeChat compile-and-freeze reports, or linked-data (JSON-LD/RDF/SPARQL over MCP results) applications were found or checked.
- **Backend specifics still unverified:** Splunk's field extractor (all doc paths returned 403/404; described from product knowledge only); Confluence `excerpt` allowed values and highlight marker format; Jira enhanced-search paging (`nextPageToken`, `maxResults` max) from prior knowledge; PagerDuty REST rate limits; Chronosphere MCP `limit: 0` semantics and result caps; Flowpipe's function reference (`regex`/`timeadd`); the corporate Logz.io and arc/git MCP servers' actual schemas (no official Logz.io MCP was found; the reference git MCP lacks grep/pickaxe); Postman Flows/FQL and StepZen (docs unreachable, not evaluated); Slack bare-term AND/OR semantics.
- **PBE tooling:** the number of highlighted examples RegexGenerator needs, RFixer's licence, and the current availability of RoadRunner code could not be confirmed from primary sources; Kushmerick's details come from the 2006 survey rather than the original papers.
